# 本地研究网站

网站需要同时运行 Python 数据后端和 Sites 前端，仅打开页面不能启动数据服务。

在项目根目录的终端启动后端：

```sh
.venv/bin/python scripts/dev_research.py
```

另一个终端启动前端（需要 Node 22.13+ 和 pnpm）：

```sh
cd sites/lianqi
pnpm run dev --host 127.0.0.1
```

访问 http://localhost:3000/，保持两个终端运行。开发前端默认连接 `http://127.0.0.1:8080`，可用 `LIANQI_ORIGIN_URL` 显式覆盖；生产 Worker 必须配置该变量，不再隐式连接固定 VPS。

本地入口禁用 Discord，监控列表、告警和模拟跟踪保存在 `runtime/local-research/`，不会覆盖根目录原始记录。历史报告仍从项目 `reports/` 读取。新信号会开始模拟跟踪，没有开仓信号时显示空记录属于正常情况。

2026-09-07 功能排查：预览和后端未运行、开发前端误接旧后端，以及保存币种时同步交易所校验阻塞事件循环。已分别修复开发连接、接口版本校验、请求等待提示和校验线程隔离。支持 SSE 推送及每 30 秒状态轮询。

实际请求验证：300 根回测约 1.4 秒，30000 根全止损对比约 86 秒；首次默认值改为 3000，样本范围不是策略有效性结论。网络诊断的外部数据源可用性随网络变化；本地 Discord 为禁用状态。此次只修复本地工作区，线上站点和 VPS 尚未更新。

浏览器操作验收：行情价格和新告警更新；切换 BTC 支撑开关并保存，刷新及后端重启后保留，再恢复原设置；默认 3000 根回测显示两种止损结果；诊断显示 Binance、Gate、CoinGecko 及浏览器直连成功；报告列表显示本地 17 份报告，首份报告正文正常打开。模拟跟踪当前无开仓样本，开仓至退出的行为由回归测试覆盖，本次没有等待完整市场信号周期。

验证命令：`.venv/bin/python -m unittest discover -s tests`（148 项通过）；Sites 目录 `pnpm test`（构建及 6 项测试通过）、`pnpm exec eslint app worker tests`（通过）。

## 当前统一入口（2026-09-08）

从仓库根目录运行 `.venv/bin/python scripts/dev_product.py`，原网站位于
`http://localhost:3000`，Python API 位于 `http://127.0.0.1:8080`。
启动器同时管理两个进程，端口已占用时停止，不启动重复实例。前端需要事先在
`sites/lianqi` 安装依赖（Node >=22.13，`pnpm install`）。

五个入口分别负责：总览、行情与信号、模拟交易、策略研究、设置与诊断。
设置保存到 `runtime/local-research/runtime-settings.json`；每次保存保留版本快照。
监控列表、模拟账本、实验归档与飞书队列也保存在该目录，重启恢复。
历史根目录账本和服务器账本不会自动合并进本地实验，避免重复信号和来源混淆。

模拟开仓不需要 API Key。保存策略配置从下一次信号计算生效；已有记录保留开仓时费用和退出规则。
关闭新记录开关不停止已有记录的退出管理。历史未记录版本的交易会明确显示为历史记录。
研究采用 Binance USDT 合约收盘 K 线；单次实验参数不修改运行参数，成功结果自动归档。
逐笔收益不是组合净值；盘口撮合、滑点及资金费尚未模拟，不能据此直接认定实盘表现。

飞书 Webhook 在设置页按渠道保存到本机私有文件（0600），不回显。
自动推送默认关闭，关闭后保留待发送队列；开启后续发。
环境变量 `NOTIFICATIONS_FORCE_OFF=true` 用于本地无发送验收，覆盖页面总开关；去掉后重启可恢复按设置控制。
当前程序不会启动交易所执行；`binance_demo.py` 等仅为未接入的扩展代码。

### 页面职责调整

第五入口现为“运行状态”。网页只展示运行规则摘要、服务异常和通知状态，
不再提供运行参数编辑、飞书地址编辑、测试消息或手动网络检测按钮。
配置变更和通知排查由后台处理；后台接口与已保存配置保留。
