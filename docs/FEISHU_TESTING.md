# 飞书通知与网站联调

本轮实现测试链路：网站「诊断 → 飞书通知联调」分别向信号、系统、研究渠道发送固定测试消息，并显示飞书接口回执和测试编号。不会写入模拟交易或策略信号记录。

配置在根目录 `.env`：

- `FEISHU_SIGNAL_WEBHOOK_URL`
- `FEISHU_SYSTEM_WEBHOOK_URL`
- `FEISHU_RESEARCH_WEBHOOK_URL`
- `FEISHU_TEST_ENABLED`：默认关闭，本地 `scripts/dev_research.py` 开启。
- `FEISHU_SITE_URL`：可选的 HTTPS 网站地址。未配置时明确提示 localhost 仅本机可用。

所有消息包含「炼气」，与机器人关键词设置匹配。Webhook 不传给前端，也不包含在错误信息中。测试接口只接受 JSON POST，渠道固定，串行执行且间隔至少 3 秒。发送超时 12 秒，不自动重试不确定结果，避免重复通知。状态保存在进程内，重启后清空。

## 自动业务通知（2026-09-07 后续接入）

本地入口已开启 `FEISHU_AUTO_ENABLED=true`。每 5 秒检查与网站相同的模拟交易记录、HTML 报告目录及监控异常状态：新信号和模拟退出发到信号群，异常与恢复发到系统群，新报告与更新发到研究群。首次启动建立历史基线，不补发旧信号和旧报告。

`FEISHU_OUTBOX_FILE` 在本地入口指向 `runtime/local-research/feishu-outbox.json`。队列及已观察记录原子落盘，发送失败指数退避重试（最长间隔 300 秒），每轮最多处理 3 条到期消息；等待重试的消息不阻塞其他渠道。自动通知可能在网络超时后重试，因此不能保证绝对只投递一次，消息包含稳定编号供核对。以上重试策略只适用于自动通知，手动测试不重试。整个进程停止时无法自行报警。

网站诊断页每 10 秒刷新自动任务状态、待发送数量和错误。通知在独立后台任务中发送，不阻塞行情监控。当前仅本机启用，未部署 VPS；手机访问暂不调整。

验证：Python 155 项、前端 6 项测试通过，前端构建通过。新增回归覆盖开仓/退出分流、历史去重、故障恢复、报告更新、重启保留失败队列、重试不阻塞其他渠道。真实生成 `feishu-auto-integration-20260907/report.html` 后，研究群自动收件；在飞书点击链接成功打开同名网站报告。未向真实模拟账本插入测试持仓，真实行情开仓至退出的完整周期仍待自然触发验证。

## 综合复测与顺序修复

2026-09-07 综合测试编号 `composite-1788789285`：隔离夹具生成开仓、报告、故障、退出、恢复共 5 条通知。先注入发送失败，验证队列重载后保留，再恢复投递；3 个真实群均收到带「综合测试」标识的消息。重复观察与重新载入后没有新待发送记录。测试夹具没有写入网站真实模拟账本。

追加测试发现：开仓失败后，后来的退出消息可能越过它。已修复为同一渠道先进先出，失败或等待重试时暂停该渠道，其他渠道仍可处理。回归先复现 `open, closed, report` 的错误次序，再验证 `open, report`，恢复后按 `open, closed` 投递。网站模拟生命周期与通知输入组合回归也验证：开仓在网站可见、退出后移入历史，对应通知各一条。完整 Python 测试 157 项通过，前端 6 项通过；本地服务已加载修复。

顺序保证是本地发送顺序，不保证网络超时后飞书绝不重复收件。若某渠道永久配置错误，该渠道后续消息会排队，网站显示待发送数量；需要修复配置后恢复。

实际报告回链复核进一步发现旧服务被 SSE 长连接拖住退出，同一报告出现两个相同编号的通知。已清理旧进程，增加 `SenderLease` 操作系统文件锁，同一个 outbox 只允许一个服务发送；本地启动器设置 `timeout_graceful_shutdown=5`。锁冲突时新任务显示初始化失败，需要旧实例释放后重启新服务，不会静默并发发送。新增锁占用/释放回归，完整 Python 测试更新为 158 项通过。
