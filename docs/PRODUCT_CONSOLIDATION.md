# 炼气本地产品整合验收

目标：继续使用 `sites/lianqi` 的原网站和本地 Python 接口；当前仅使用 Binance
公开合约行情、本地模拟开仓/退出，不要求交易所 API Key，不启动交易所执行。

待验收范围：
- 五个入口：总览、行情与信号、模拟交易、策略研究、设置与诊断。
- 唯一当前模拟账本，历史保留；重复页面/独立交易执行不进入当前流程。
- 运行设置可校验、保存、读取；明确生效范围与版本，刷新/重启不丢失。
- 新信号/模拟交易保存配置版本，现有交易保留开仓时费用与退出规则。
- 研究与实时跟踪使用相同合约数据口径及共享策略；研究参数不会暗改运行配置。
- 研究结果携带数据范围、参数和版本，保存后可重新打开。
- 飞书配置、发送开关、状态可用；故障按完整扫描汇总，避免中途误报恢复。
- 页面显示实际服务/数据状态；提供统一的本地启动方式。
- 离线行为测试、前端构建/组件测试及本地接口验收证明上述链路。

GitHub 参考：Freqtrade/FreqUI 的本地 dry-run 与运行配置分离；Jesse 的实验归档；
Hummingbot Dashboard 的配置和运行实例对应。复用现有策略核心，不搬入另一套交易框架。

完成证据将在各项实现后更新；此文件不是已完成声明。

## 本地验收结果

已实现五入口、配置版本保存和冲突检测、唯一当前账本、旧交易费用冻结、
同源合约回测及实验归档、飞书地址保存和动态开关。原官方 Demo CLI 与 Compose
执行入口已停用，独立纸面机器人 CLI 已退休，适配器代码仅留作扩展。
原网站沿用 `sites/lianqi`，本地启动命令为 `.venv/bin/python scripts/dev_product.py`。

验证：运行配置经过网站代理 PUT 后再次 GET 一致；真实 BTCUSDT 15m 回测取得
299 根已收盘 K 线，结果 `ok=true`，归档再次 GET 可读。该短样本没有成交，
仅验证链路，未证明策略盈利。运行接口取得两个监控交易对的行情与信号，
当次 `last_error=null`。本地验收使用 `NOTIFICATIONS_FORCE_OFF=true`，没有发送飞书消息。

异常处理：按币种隔离 TypeError，按模块维护错误、完整周期发布汇总；相同故障
持久去重，恢复需持续 60 秒，通知失败队列保留并退避重试。

实际边界：本地纸面收益没有盘口撮合、资金费或滑点；并非账户净值。
历史 OKX 研究与旧账本保留，不自动混入当前本地账本。
未部署服务器；前端验收使用构建、TypeScript、SSR/代理测试和 HTTP 请求，未进行视觉截图验收。

最终自动检查：Python 200 项通过；前端 6 项通过（含五个导航入口及代理行为）；
TypeScript、生产构建和 ESLint 均通过。保存的配置与实验经过本地服务重启后再次读取确认。

## VPS 发布结构

Docker 构建同一份 React 页面为 `/site/` 静态资源，由 Python 服务在 `/` 提供，
不需要在 VPS 启动另一套前端进程。运行配置写接口仅允许服务器本机调用。
GitHub 不包含密钥、账本、报告和构建缓存。

旧 OKX 服务采用原镜像与 `scripts/legacy_okx_drain.py` 过渡：开仓入口强制拒绝、
容量为 0，只处理既有持仓；账本和交易所均确认无持仓后正常退出，容器不再重启。
